# Atlas の MCP 接続

Atlas は MCP（Model Context Protocol）のリモートサーバーを提供します。Claude Code や Codex などの MCP クライアントから、ブラウザーを操作せずに Atlas のタスク・プロジェクト・コメントを参照・更新できます。

- 接続には **OAuth 2.1（推奨）** または **個人アクセストークン（PAT）** を使います。
- 使える操作は、**接続した本人が Atlas で持っている権限の範囲内**だけです。プロジェクトの閲覧権限や編集権限、ワークスペースの RBAC を毎回確認します。
- **ゲストユーザーは MCP を使えません。** PAT の発行、OAuth の承認、トークンでの接続のすべてで拒否されます。
- MCP は**出荷時は無効**です。管理者が「管理 → セキュリティ → MCP 接続」で有効にするまで接続できません。

> このドキュメントの `https://atlas.example.com` は、自分の Atlas の URL に読み替えてください。本番は HTTPS を使ってください。

## 1. できること

MCP のツールは次の 18 個です。`read` は参照、`write` は作成・更新・論理削除です。ツール一覧はトークンのスコープと接続先に応じて絞り込まれ、読み取り専用の接続には `write` のツールが表示されません。

| ツール | 種別 | 概要 |
| --- | --- | --- |
| `whoami` | `read` | 認証中のユーザー、実効スコープ、接続先（`default` / `readonly`）を返します。 |
| `list_projects` | `read` | 閲覧できるプロジェクトの一覧を返します。カーソル方式（既定 25 件、最大 100 件）。 |
| `get_project` | `read` | プロジェクトの基本情報とセクション一覧を返します。 |
| `list_sections` | `read` | プロジェクトのセクション一覧を返します。 |
| `list_tasks` | `read` | プロジェクト、担当者（`me` またはユーザー ID）、状態、完了状態、期限、キーワードでタスクを検索します。 |
| `get_task` | `read` | タスクの詳細を返します。説明は既定で 2,000 文字までに切り詰められ、続きは `includeFullDescription` で取得します。 |
| `list_comments` | `read` | タスクのコメントを古い順に返します。 |
| `list_my_tasks` | `read` | 自分に割り当てられた未完了タスクを返します。サブタスクも含み、親タスクの情報も返します。 |
| `list_users` | `read` | ワークスペースのユーザー一覧を返します。 |
| `list_project_members` | `read` | プロジェクトのメンバーとプロジェクトロールを返します。 |
| `list_custom_fields` | `read` | プロジェクトのカスタムフィールド定義を表示順に返します。 |
| `save_task` | `write` | `id` なしでタスクを作成、`id` ありで更新します。担当者、開始日、期限、状態、セクション、親タスク、マイルストーン、カスタムフィールドを扱えます。 |
| `complete_task` | `write` | タスクを完了または未完了にします。 |
| `move_task` | `write` | 同じプロジェクト内の別セクションへタスクを移動します。 |
| `add_comment` | `write` | タスクに Markdown コメントを追加します。 |
| `save_section` | `write` | プロジェクトにセクションを作成します（前後の位置を指定できます）。名前変更や並べ替えはできません。 |
| `save_project` | `write` | `id` なしでプロジェクトを作成、`id` ありで更新します。テンプレートからの作成にも対応します。 |
| `trash_task` | `write` | タスクをゴミ箱へ移します（論理削除のみ）。Atlas の画面から復元できます。完全削除はできません。 |

補足:

- 一覧系のツールはカーソル方式です。既定は 25 件、最大 100 件です。
- 日付は `YYYY-MM-DD` で指定します。
- 作成系のツールは `idempotency_key` を受け付けます。再送しても二重に作成しません。
- タスクの更新系（`save_task` の更新、`complete_task`、`move_task`）は `expected_updated_at` を受け付けます。他の利用者が先に更新していた場合は、上書きせずに競合として失敗します。
- `save_project` の作成にはワークスペースの `projects.create` 権限、更新にはプロジェクトの設定権限が必要です。タスクの作成・更新にはプロジェクトの編集権限、コメントにはコメント権限、セクションの作成にはプロジェクトの設定権限が必要です。
- ツールの引数と戻り値の詳細は、接続後にクライアントが表示するツール定義を参照してください。

## 2. 接続先

| 用途 | URL | 説明 |
| --- | --- | --- |
| 読み取りと書き込み | `https://atlas.example.com/mcp` | トークンに `write` がある場合だけ書き込みツールを公開します。 |
| 読み取り専用 | `https://atlas.example.com/mcp/readonly` | トークンに `write` があっても書き込みツールを公開しません。 |

- MCP は `POST` のみを受け付けます。`GET` は 405 を返します。
- 読み取り専用の接続先でも、`read` のツールはすべて使えます。
- OAuth のアクセストークンは接続先ごとに発行されます。`/mcp` 用のトークンで `/mcp/readonly` に接続すると 401 になります（逆も同じです）。両方使う場合は、クライアントに 2 つの接続を登録してください。
- PAT はどちらの接続先でも使えます。読み取り専用の接続先では、`read write` の PAT でも書き込みはできません。

## 3. 接続方法（利用者）

### 3.1 OAuth（推奨）

OAuth では、クライアントに URL を登録するだけで接続できます。トークンをコピーする必要はありません。

1. クライアントに MCP サーバーの URL を登録します。
2. クライアントが Atlas のメタデータを読み取り、ブラウザーで承認画面を開きます。
3. Atlas にログインしていない場合は、パスワードまたは SAML でログインし、必要なら 2 段階認証を済ませます。
4. 承認画面で内容を確認し、「許可する」を押します。
5. クライアントに戻り、接続が完了します。

#### 承認画面で確認すること

承認画面には次の項目が表示されます。

| 項目 | 内容 |
| --- | --- |
| クライアント | アプリ名と、クライアントのメタデータ URL のホスト（動的に登録されたアプリの場合はその旨）。 |
| 戻り先 | 「このコンピューター上のアプリ」（ループバック）または接続先のホスト。 |
| 接続先 | `/mcp` または `/mcp/readonly`。読み取り専用の場合はその旨も表示されます。 |
| 要求された権限 | 「読み取りと書き込み」または「読み取り」。 |
| ログイン中のユーザー | 承認する Atlas アカウント。 |

クライアント名はクライアントが申告する値です。**アプリ名だけで判断せず、メタデータ URL のホストと戻り先も確認してください。** 心当たりのないアプリや戻り先には許可を与えないでください。

「読み取りのみ許可する」は、`/mcp` に対する承認で書き込み権限が要求されたときに表示されます。オンにすると、その接続は参照だけになり、書き込みツールは公開されません。`/mcp/readonly` に接続した場合も同じく書き込みはできません。

#### Claude Code

```bash
claude mcp add --transport http atlas https://atlas.example.com/mcp
```

初回の接続時にブラウザーで承認します。承認画面が開かない場合は、次のコマンドで認証を開始できます。

```bash
claude mcp login atlas
```

読み取り専用で使う場合は、別名で読み取り専用の URL を登録します。

```bash
claude mcp add --transport http atlas-readonly https://atlas.example.com/mcp/readonly
```

`--transport http`、`--header`、`mcp login <name>` は Claude Code 2.1.330 の `claude mcp add --help` / `claude mcp --help` で確認しています。フラグの意味や承認の表示はクライアントのバージョンで変わるため、最新の公式ドキュメントも参照してください。Claude Code の OAuth で承認画面が開かない場合は `claude mcp login atlas` を実行し、それでも接続できない場合は PAT を使ってください。

#### Codex

`~/.codex/config.toml` に次のように追加します。

```toml
[mcp_servers.atlas]
url = "https://atlas.example.com/mcp"
```

追加したら、ブラウザーで承認します。

```bash
codex mcp login atlas
```

CLI から登録する場合は次のとおりです。

```bash
codex mcp add atlas --url https://atlas.example.com/mcp
codex mcp login atlas
```

読み取り専用で使う場合は、URL を `https://atlas.example.com/mcp/readonly` にした別名のサーバー（例: `atlas-readonly`）を追加し、その名前でログインします。

`codex mcp add <name> --url <url>` と `codex mcp login <name>` は Codex CLI 0.171.0-alpha.13 の `codex mcp add --help` / `codex mcp login --help` で確認しています。Codex の OAuth では、`codex mcp login atlas --scopes read` のように要求スコープを読み取りだけにすることもできます（同じバージョンの `--help` で確認）。クライアントの表示やオプションはバージョンで変わるため、公式ドキュメントも参照してください。

### 3.2 個人アクセストークン（PAT）

PAT は、OAuth を使えないクライアントや、決まったトークンを継続して使いたい場合の方法です。管理者が「MCP 接続」と「個人アクセストークンを許可」の両方を有効にしている場合だけ発行できます。

1. プロフィール画面の「MCP 接続」を開きます。
2. 「個人アクセストークン」の「トークンを発行」を押します。
3. 名前（例: 自宅の Claude Code）と権限（「読み取りと書き込み」または「読み取りのみ」）を選びます。
4. 発行されたトークンをコピーします。**この画面を閉じると再表示できません。** Atlas は SHA-256 ハッシュだけを保存します。
5. クライアントの `Authorization: Bearer` ヘッダーに設定します。

PAT に有効期限はありません。失効させるまで有効です。発行画面には期限の項目がなく、一覧には最終使用日時が表示されます。使っていないトークンは失効させてください。

#### Claude Code で PAT を使う

```bash
claude mcp add --transport http atlas https://atlas.example.com/mcp \
  --header "Authorization: Bearer <TOKEN>"
```

`--header`（短縮形 `-H`）は Claude Code 2.1.330 の `claude mcp add --help` で確認しています。

#### Codex で PAT を使う

`~/.codex/config.toml` で環境変数を参照するように設定します。

```toml
[mcp_servers.atlas]
url = "https://atlas.example.com/mcp"
bearer_token_env_var = "ATLAS_MCP_TOKEN"
```

トークンを環境変数に設定してから Codex を起動します。

```bash
export ATLAS_MCP_TOKEN="<TOKEN>"
```

CLI から登録する場合は次のとおりです。

```bash
codex mcp add atlas --url https://atlas.example.com/mcp \
  --bearer-token-env-var ATLAS_MCP_TOKEN
```

`--bearer-token-env-var` は Codex CLI 0.171.0-alpha.13 の `codex mcp add --help` で確認しています。`bearer_token_env_var` はプロフィール画面の接続設定でも案内している設定です。

読み取り専用で使う場合は、発行時に「読み取りのみ」を選ぶか、接続先を `/mcp/readonly` にします。両方を使うと、書き込み可能な接続と読み取り専用の接続を併用できます。

> トークンを設定ファイルに直接書くと、リポジトリやバックアップに残る可能性があります。環境変数や OS のシークレット管理機能を使ってください。漏えいが疑われる場合は、すぐにプロフィール画面から失効させます。

## 4. スコープと有効期限

### スコープ

| スコープ | 内容 |
| --- | --- |
| `read` | 参照系ツールすべて。閲覧権限のあるプロジェクトのデータだけを返します。 |
| `write` | 作成・更新・論理削除のツール。`read` を含みます。加えて、対象プロジェクトの編集・設定権限や、ワークスペースの `projects.create` 権限が必要です。 |

実効権限は次の積集合です。

```
利用者の現在の Atlas の権限（プロジェクトロール + RBAC）
  ∩ トークンのスコープ（read / write）
  ∩ 接続先（/mcp または /mcp/readonly）
```

- 権限はツールを実行するたびに最新の状態で判定されます。ロール変更、プロジェクトからの除名、無効化は次の呼び出しから反映されます。
- OAuth で `scope` を指定しない場合の既定は `read write` です。承認画面で「読み取りのみ許可する」を選ぶと `read` だけのトークンになります。
- PAT の既定は「読み取りと書き込み」です。発行画面で「読み取りのみ」に変更できます。
- 読み取り専用にしたい場合は、次のどれかを使います。
  1. `/mcp/readonly` に接続する（サーバー側で書き込みツールを公開しない）
  2. OAuth の承認画面で「読み取りのみ許可する」を選ぶ
  3. 「読み取りのみ」の PAT を発行する
- 書き込みはトークン単位で 1 分あたり 20 回までに制限されています。認証の失敗はクライアント IP 単位で 15 分あたり 60 回までに制限されています。

### 有効期限

| 種類 | 有効期限 | 補足 |
| --- | --- | --- |
| PAT | なし | 本人または管理者が失効させるまで有効です。最終使用日時を一覧で確認できます。 |
| OAuth アクセストークン | 24 時間 | 期限が切れるとクライアントがリフレッシュトークンで更新します。 |
| OAuth リフレッシュトークン | 30 日 | 更新のたびに新しいリフレッシュトークン（発行から 30 日）に交換されます。30 日間使わないと再承認が必要です。 |
| OAuth 認可コード | 10 分 | 承認後にクライアントがトークンと交換するための短命なコードです。 |

- リフレッシュトークンはローテーションされます。使用済みのリフレッシュトークンが再利用された場合は、その接続のトークン系列全体が失効します。
- OAuth のアクセストークンは `/mcp` と `/mcp/readonly` のどちらか一方にだけ有効です。
- MCP を無効にしている間や、個人アクセストークンを許可していない間は、該当するトークンを使えません。有効期限とは別の制御です。

## 5. 連携の解除と失効

### 利用者による解除

プロフィール画面の「MCP 接続」で管理します。

- **接続済みアプリ（OAuth）**: アプリごとに「連携を解除」を押すと、その接続のアクセストークンとリフレッシュトークンがまとめて失効します。利用中のクライアントは 401 になり、再接続にはもう一度承認が必要です。
- **個人アクセストークン（PAT）**: 一覧の「失効」を押すと、そのトークンがすぐに使えなくなります。元に戻せません。接続中のクライアントには新しいトークンを設定してください。

### 管理者による強制失効

「管理 → セキュリティ → MCP 接続」の「接続中のトークン」から、ワークスペース内の PAT または OAuth の連携を失効できます。この操作は super 管理者だけが行えます。詳細は「6. 管理者向け」を参照してください。

### 自動で失効する場合

次の操作では、そのユーザーの MCP トークン（PAT と OAuth）が自動的に失効します。

- 管理者または SCIM によるユーザーの無効化
- ユーザーのゲスト化（ロール変更）
- 管理者によるパスワードリセット
- 管理者による 2 段階認証のリセット

**利用者本人によるパスワード変更では、MCP トークンは失効しません。** パスワードを変更した理由が漏えいの疑いである場合は、プロフィール画面でトークンも失効させてください。

OAuth のリフレッシュトークンの再利用を検出した場合も、その接続系列が失効します。

### 管理者が MCP を無効にした場合

「MCP 接続を許可」をオフにすると、発行済みのトークンもすぐに使えなくなります。ただし、これはトークンの失効ではありません。再度オンにすると、失効せず有効期限も切れていないトークンは再び使えます。不要なトークンは個別に失効させてください。

「個人アクセストークンを許可」をオフにした場合は、PAT だけが使えなくなります。OAuth の接続は影響を受けません。

## 6. 管理者向け

### 6.1 設定

「管理 → セキュリティ → MCP 接続」を開きます。

- **初期状態**: MCP 接続と個人アクセストークンはどちらも無効です。
- **変更できる人**: super 管理者だけです。通常の管理者には状態と接続先 URL が読み取り専用で表示されます。
- **MCP 接続を許可**: メンバーが OAuth または PAT で MCP に接続できるようにします。オフの間は、すべての MCP リクエストが認証で拒否されます。
- **個人アクセストークンを許可**: メンバーがプロフィール画面で PAT を発行できるようにします。MCP 接続が有効で、かつこの設定も有効な場合だけ発行できます。オフにしても OAuth は使えます。
- **ゲスト**: ゲストは MCP を使えません。設定にかかわらず、PAT の発行・OAuth の承認・トークンでの接続を拒否します。
- **接続先 URL**: 画面に `/mcp` と `/mcp/readonly` が表示されます。コピーして利用者に案内できます。

MCP 接続をオフにしてもトークンは失効しません。オフの間に使えなくなるだけで、再度オンにすると失効していないトークンは再び使えます。無効化したままにする場合は、必要に応じて「接続中のトークン」から失効させてください。

### 6.2 接続中のトークンとリクエストログ

「接続中のトークン」と「リクエストログ」は super 管理者だけに表示されます。

「接続中のトークン」には、現在認証に使える資格情報が表示されます。

- PAT は 1 トークン 1 行です。
- OAuth はリフレッシュトークンの系列（連携）ごとに 1 行にまとまります。
- 表示項目は、ユーザー、名前またはクライアント名、権限（読み取りのみ / 読み取りと書き込み）、作成日または初回承認日、最終使用日時、OAuth の接続先です。
- 「失効」で PAT または OAuth 連携をすぐに無効化できます。失効したトークンは一覧から消えます。

「リクエストログ」には、MCP への接続とツール呼び出しの結果が新しい順に表示されます。

- 結果（成功 / エラー / 拒否 / 未認証）で絞り込めます。1 ページ 50 件で、「さらに読み込む」で続きを表示します。
- 表示項目は、日時、結果、ツール名または RPC メソッド、エラーコード、ユーザー、クライアント名、所要時間、接続先、クライアント IP、トークン名です。
- リクエスト本文、ツールの引数、`Authorization` ヘッダー、トークンの値は保存しません。
- 保持期間は既定で 30 日です。`server.js` の日次 janitor が `RETENTION_DAYS_MCP_LOGS`（既定 30）に従って削除します。

認証に失敗した理由（`invalid`、`revoked`、`expired`、`disabled`、`guest`、`inactive_user`、`audience` など）は `error_code` に記録されます。クライアントに返る本文は `{"error":"invalid_token"}` だけなので、原因調査にはこのログを使ってください。

### 6.3 監査ログとタスク履歴

MCP からの書き込みは、監査ログに `via=mcp`、トークン ID、クライアント名付きで記録されます。監査画面では「MCP経由（クライアント名）」と表示されます。タスクの履歴にも「MCP経由（クライアント名）」が表示されます。

2025 年版のプロトコルを使うクライアント（例: Codex 0.171.0-alpha.13）は、ツール呼び出し時にクライアント名を送らないことがあります。PAT で接続している場合はクライアント名が空になり、「MCP経由」だけが表示されることがあります。OAuth では、トークンに保存されたクライアント名が使われます。

### 6.4 本番環境の設定

- **`APP_URL` または `APP_ORIGIN` が必須です。** 本番でどちらも設定されていない場合、OAuth のメタデータは 500 を返し、トークンがない・無効なときの応答も 500 になります。OAuth を開始できないため、実質的に MCP へ接続できません。`APP_URL` が `APP_ORIGIN` より優先されます。末尾スラッシュなしの絶対 URL（例: `https://atlas.example.com`）を設定してください。
- `APP_URL` / `APP_ORIGIN` のホスト名は、MCP の Host / Origin 検証でも使われます。未設定の本番ではループバック（`localhost`、`127.0.0.1`、`[::1]`）以外の Host が 403 になります。
- HTTPS を使ってください。OAuth のリダイレクト URI は `https` とループバック（`http://localhost:*` / `http://127.0.0.1:*`）だけを許可します。
- nginx などのリバースプロキシは、`/mcp`、`/mcp/readonly`、`/oauth/*`、`/.well-known/oauth-*` をそのままアプリへ通します。専用の `location` は不要です（`deploy/nginx/atlas.conf` の既定の `location /` が通します）。`Authorization` と `WWW-Authenticate` を削除しないでください。MCP クライアントは 401 の `WWW-Authenticate` から OAuth を開始します。
- `/.well-known/` 全体を横取りする設定を追加しないでください。ACME のチャレンジはポート 80 の webroot だけで扱っています。

## 7. セキュリティ上の注意

- **タスク名・説明・コメントなどはデータであり、AI への指示ではありません。** ツールの説明にも同じ注意を書いています。Atlas のデータに「この指示に従って」といった文章が含まれていても、AI に実行させないでください。サーバー側は権限外の操作を拒否しますが、トークンの権限内の操作は実行できてしまいます。
- **承認前に確認する。** クライアント名、メタデータ URL のホスト、戻り先、接続先、権限を確認し、心当たりのない接続は許可しないでください。
- **トークンを安全に保管する。** PAT は発行時に一度だけ表示され、Atlas にはハッシュだけが保存されます。チャット、Issue、リポジトリ、スクリーンショットに貼らないでください。環境変数やシークレット管理機能を使い、漏えいが疑われる場合はすぐに失効させます。
- **読み取り専用を既定にする。** 参照だけで足りる接続には `/mcp/readonly`、読み取り専用 PAT、承認画面の「読み取りのみ許可する」のいずれかを使ってください。書き込みが必要な接続だけ `write` を許可します。
- **監査ログを確認する。** MCP からの書き込みは `via=mcp` として記録されます。不審な操作があれば、管理画面のリクエストログと監査ログを確認し、該当トークンを失効させてください。
- **ゲストと無効化ユーザーをブロックする。** ゲスト化・無効化・管理者によるパスワード / 2FA リセットでは、そのユーザーのトークンが自動的に失効します。
- **完全削除はできない。** `trash_task` はゴミ箱へ移すだけで、Atlas の画面から復元できます。MCP からワークスペース管理操作（ユーザー管理、ロール、SAML / SCIM 設定など）はできません。

## 8. トラブルシューティング

### 401 `invalid_token` が返る

クライアントには `{"error":"invalid_token"}` だけが返り、詳しい理由は返りません。管理画面のリクエストログで `error_code` を確認してください。主な原因は次のとおりです。

- `Authorization: Bearer` ヘッダーがない、トークンの値が違う。
- トークンが失効している（`revoked`）。プロフィールで失効した、管理者が失効した、ユーザーが無効化・ゲスト化された、管理者がパスワード / 2FA をリセットした、など。
- OAuth のアクセストークンが期限切れ（`expired`）。クライアントがリフレッシュできていない場合は、再接続して承認し直します。
- MCP 接続が無効（`disabled`）。管理者に有効化を依頼します。
- PAT を使っているが、個人アクセストークンが許可されていない（`disabled`）。
- ユーザーが無効化されている、またはゲストになっている（`inactive_user` / `guest`）。
- OAuth のトークンの接続先が違う（`audience`）。`/mcp` 用のトークンで `/mcp/readonly` に接続していないか確認し、接続先ごとに承認し直します。

まず `whoami` を実行すると、認証中のユーザー、実効スコープ、接続先を確認できます。それでも分からない場合は、トークンを発行し直すか、OAuth で再接続してください。

### HTTP 403 が返る

Host または Origin の検証で拒否されています。

- リバースプロキシが `Host` を変えていないか確認します。
- 本番で `APP_URL` / `APP_ORIGIN` が正しく設定されているか確認します。未設定だとループバック以外の Host が拒否されます。
- ブラウザー以外のクライアントが `Origin` を送る場合、その Origin が公開 URL と一致しているか確認します。
- OAuth の承認 POST を別のオリジンから送っていないか確認します。承認は同じオリジンから行う必要があります。

### 承認画面のエラー

| 表示 | 意味と対処 |
| --- | --- |
| 「このクライアントは登録されていないか、無効になっています。接続元のアプリからやり直してください。」 | クライアントの登録を解決できませんでした。クライアント側で接続を削除して追加し直し、もう一度承認を開始してください。 |
| 「認可リクエストが正しくありません。クライアントの登録内容と戻り先の URL を確認してください。」 | 戻り先が登録内容と一致しないなど、認可リクエストが不正です。クライアントを更新するか、接続を追加し直してください。 |
| 「管理者が MCP 接続を有効にすると利用できます。」 | ワークスペースで MCP が無効です。管理者に有効化を依頼してください。 |
| 「サーバーの公開 URL が設定されていません。管理者に連絡してください。」 | 本番で `APP_URL` / `APP_ORIGIN` が設定されていません。管理者が設定します。 |
| ログイン画面や 2 段階認証に戻される | Atlas にログインしていないか、MFA が未完了です。ログインと MFA を済ませると承認画面に戻ります。 |
| ゲストとして拒否される | ゲストは MCP を使えません。メンバーのアカウントで接続してください。 |

### 接続先 URL が違う

- `https://atlas.example.com/mcp` または `https://atlas.example.com/mcp/readonly` をそのまま使います。`/mcp/` や `/mcp/tools` のような別のパスにしないでください。
- 本番は HTTPS です。HTTP の URL は使いません。
- ブラウザーで `GET /mcp` を開くと 405 になります。MCP クライアントの HTTP トランスポートから `POST` で接続します。
- OAuth のメタデータは `APP_URL` / `APP_ORIGIN` を基準に生成されます。公開 URL を変えた場合は、クライアントに登録した URL も更新し、OAuth をやり直してください。

### 書き込みツールが表示されない

- 接続先が `/mcp/readonly` になっていないか確認します。
- PAT の権限が「読み取りのみ」になっていないか確認します。
- OAuth の承認で「読み取りのみ許可する」を選んでいないか確認します。
- `whoami` の `scopes` と `endpoint` で、実効スコープと接続先を確認できます。
- 書き込みツールがあっても、対象プロジェクトの編集権限がなければ実行時に拒否されます。

### 429 が返る

- 書き込みの回数制限（1 分あたり 20 回）に達しています。時間を置いて再試行してください。
- 認証の失敗が続くと、IP 単位の制限（15 分あたり 60 回）にかかることがあります。トークンと接続先を確認してから再試行してください。
