# 認証の暗号化・試行制限・SAMLセッション失効

2026-11-11。基準コミット `16e0bb9`。既存DB・3,000件の操作用環境・確認用環境には適用せず、新規の使い捨て環境だけで検証します。

## 二要素認証の秘密鍵

`totp_secret` と `totp_pending_secret` はAES-256-GCMの暗号文だけを保存します。ランダムnonce、認証タグ、版、鍵IDを持ち、ユーザーID・用途・版・鍵IDも認証対象にします。別ユーザーや登録途中から有効済みへの暗号文コピーは復号できません。有効化時は用途を変えて再暗号化します。

鍵は `MFA_ENCRYPTION_KEY_ID` と `MFA_ENCRYPTION_KEYS` でサーバーに供給します。実値をリポジトリに保存しません。32バイトのランダム鍵をBase64で設定し、DBのバックアップとは別に保管してください。雛形は `.env.mfa.example`、移行・鍵交換の手順は `mfa-secret-encryption.md` を参照してください。

`0018_mfa_secret_encryption.sql` はNode側の移行処理と同じトランザクションで既存平文を暗号化し、DB制約で平文の再書き込みを拒否します。既存秘密鍵があるのに鍵設定が不足・不正なら、その移行をロールバックします。秘密鍵がない空DBは鍵未設定でも起動できますが、MFA設定・TOTP検証は503で停止します。平文フォールバックや既定鍵はありません。登録用QRと復旧コードを含むMFA応答は `no-store` です。

## 認証APIの試行制限

PostgreSQLの原子的な予約で全インスタンスに共有します。Redisの利用可否で制限を省略しません。識別子はスコープを含めてハッシュ化し、メールアドレス・IP・OTP・招待トークンを制限テーブルに平文保存しません。上限超過は429と `Retry-After`、制限ストレージの障害は503を返し、認証を続行しません。

| 対象 | 上限／期間 |
|---|---|
| パスワードログイン | 同一メール40回／15分 |
| TOTP／復旧コード | 同一ユーザー10回／5分、ログインとMFA確認で共有 |
| MFA有効化・無効化の検証 | 同一ユーザー10回／5分 |
| QR登録開始 | 同一ユーザー5回／10分 |
| パスワード変更 | 同一ユーザー10回／15分 |
| 招待受諾 | 同一トークン30回／15分 |
| SAML開始・コールバック | それぞれ接続元120回／5分 |
| 全認証処理の合計 | 6,000回／分 |
| 検証済みの接続元の合計 | 500回／分 |

資格情報の検証に成功した場合は、その予約分だけ返却し、他の失敗履歴を消しません。QR開始・SAML・招待・全体枠は処理回数の制限です。復旧コードの消費・MFA有効化・検証後のセッション発行と成功分の返却を同じトランザクションに含めます。COMMITの結果が不明な障害では、二重返却を避けるため予約が期間満了まで保守的に残る場合があります。

カスタムサーバーは受信した接続元用ヘッダーを破棄し、ソケットのpeer IPにプロセス内の鍵で署名します。認証処理は署名を検証した値だけを使用します。未検証の `X-Forwarded-For` や偽造ヘッダーで枠を切り替えられません。プロキシ下ではpeerはプロキシのIPとなり、接続元枠が共有されます。カスタムサーバー以外の起動では未署名ヘッダーを信用せず、主体・全体枠を適用します。期限切れの行の削除は1回100件までです。

ログイン・プロフィールの画面では429・503を誤ったパスワードとして表示せず、入力を保持して再試行までの案内を表示します。ログアウトは制限対象にしません。

## SAML必須化と既存セッション

`0019_saml_session_policy.sql` でセッションの出自を `password` / `saml` として記録します。旧セッションは証拠のないSAML成功とみなさず、`password` 扱いにします。ユーザーIDと出自は後から変更できません。MFA完了時も新しい行へ交換し、SAML出自と元の期限を維持します。

必須設定の保存、対象の既存パスワードセッションの削除、監査ログを同一トランザクションで行います。管理者の緊急ログイン、ゲスト除外モードのゲスト、SAML由来セッションは既存仕様に従って維持します。対象ユーザーの区分変更や並行ログインでも失効を取りこぼさないよう、ポリシー→ユーザー→セッションの順にロックします。ページ・API・WebSocketも現在のポリシーを再確認します。WebSocketの既存接続は従来の定期再認可で切断します。

パスワードログインとSAMLコールバックは、最終セッション発行時にユーザーとMFA状態をロック下で再読します。認証中にMFAの有効化・リセットが完了しても古い状態を使って通常セッションを発行しません。IdP設定・SAMLで許可するURL・SP起点のみという対応範囲は変更していません。
