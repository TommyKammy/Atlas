# タイムライン性能判断（1,000タスク計測）

- 計測日: 2026-11-09
- 対象: `/projects/:id?view=timeline`
- 計測スクリプト: `scripts/bench-browser-timeline.mjs`

## 計測結果

| 指標 | 値 |
|---|---:|
| タスク数 | 1,000 |
| セクション数 | 10 |
| 描画バー数 | 1,000 |
| 最初のバー表示 | 986ms |
| DOMContentLoaded / load | 320ms |
| ズーム操作（500ms待機を除く） | 約139ms |
| レーン計算 mean / p95 | 0.11ms / 0.19ms |
| 全タスク重複の最悪ケース | 7.63ms / 1,000レーン |

## 判断

**現時点では仮想化・ページングを導入しない。**

理由:

1. 1,000タスクでも初期表示が約1秒で、操作不能な遅延ではない。
2. バー1,000個のDOMは描画・ズーム操作とも実用範囲に収まっている。
3. レーン計算は最悪ケースでも8ms未満で、ボトルネックではない。
4. 仮想化は横スクロール・依存線・ドラッグ座標・行固定の挙動を複雑にするため、
   必要性が確認できるまで導入しない方が回帰リスクが低い。

## 導入トリガー

次のいずれかを満たしたら、タイムラインの仮想化またはページングを再検討する。

- 1プロジェクトあたり2,000タスクを超える
- 初期表示（最初のバー）が2秒を超える
- ズーム・スクロール操作が100msを超える
- モバイル実機で操作不能な引っかかりが出る

## 次に取るべき対策（トリガー到達時）

1. 表示範囲外のバーをDOMから外す（横方向の仮想化）
2. 依存線・ミルストーン線は表示範囲でクリップ
3. 1,000件超では初期描画を「週単位のページング」に切り替える
4. レーン計算はセクション単位でメモ化する
