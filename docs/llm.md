# ノートのAIアシスト

管理 → AI接続で接続とモデルを登録し、使用するプロジェクトを選んで有効にします。プロジェクトごとの使用接続は1つで、利用者画面には要約・文章改善の操作を表示し、モデル名や接続先の説明は表示しません。生成APIもサーバー側の指定を使用し、別の接続ID・モデルによる上書きを拒否します。初期状態では接続も許可プロジェクトもありません。編集権限のあるユーザーだけが、ノートの閲覧画面から要約・文章改善案を生成できます。編集中の未保存データは対象にしません。

## 接続

| 方式 | API | 設定 |
| --- | --- | --- |
| OpenAI公式 | `POST https://api.openai.com/v1/responses` | APIキーと利用可能なモデルID。URLは固定、`store:false` |
| OpenAI互換 | `POST {Base URL}/chat/completions` | Base URL、モデルID、必要な場合だけAPIキー |
| MTPLX / Local Qwen | OpenAI互換 | ホスト実行なら `http://127.0.0.1:8002/v1`、Docker Desktopなら `http://host.docker.internal:8002/v1`。確認したモデルIDは `mtplx-flash-next-optimized-speed` |

接続テストはサーバーから `/models` を取得し、固定の挨拶文で実際に生成します。ノート本文は送りません。モデル一覧を返さない互換サーバーではテストは失敗しますが、対応するChat Completionsを備えていれば生成自体は可能です。モデル一覧にない別名でも生成APIが受理する場合があるため、選択IDの存在を一覧だけで拒否しません。

OpenAI互換はすべての独自拡張を保証しません。非ストリーミングの `messages` / `max_tokens` と、`choices[0].message.content` / `finish_reason:stop` に対応するサーバーが対象です。推論専用フィールドは表示・保存しません。クラウドへの自動フォールバック、ツール呼び出し、RAG、画像入力はありません。

## サーバー設定と秘密情報

- `LLM_ENCRYPTION_KEY`: 暗号学的にランダムな32バイトのBase64（例: `openssl rand -base64 32`）。MFAキーとは独立したキーを、Git管理外の環境設定または秘密管理システムから注入します。DBには保存しません。
- `LLM_ALLOWED_LOCAL_ORIGINS`: 管理者が運用側で許可したローカル接続のoriginをカンマ区切りで指定します。Dockerの例: `http://host.docker.internal:8002`。`/v1` は含めません。特定のホスト名とポートだけを登録し、広いネットワークや不要なホストを許可しないでください。

UIのキー入力は書き込み専用です。AES-256-GCMで暗号化し、接続IDを認証データとして付加します。既存キーの取得APIはありません。キーを空欄で保存すると維持し、削除チェックで消去します。接続方式やURLを変更した場合は旧キーを消去します。マスターキーを失うと保存済みAPIキーは復号できません。マスターキーを変更する場合は接続を無効にしてAPIキーを再登録してください。生成結果の保存トークンも無効になります。

外部接続はHTTPSかつ公開IPのみです。DNS解決結果を検証し、実接続をそのIPに固定します。リダイレクトは追跡しません。明示したローカルoriginにだけ例外を適用します。ローカルとして許可したプロキシが外部へ転送するかどうかはAtlasから判定できないため、その運用設定も確認してください。

Docker内の127.0.0.1はコンテナ自身を指します。Atlasは接続先を書き換えず、画面のMTPLX設定例でホスト接続のURLを案内します。既存のMTPLXプロセスやモデルを起動・停止・変更する処理はありません。

## データ保護と操作

1. 選択ノートのIDと期待する版だけを受け取り、認証済みユーザーの権限で本文を取得します。本文をリクエストJSONから受け取りません。
2. 保存済みのタイトルと本文をテキストに変換し、リンク先URL・画像の参照先は除外します。リンク先や添付ファイル、他ノート、履歴を読み込みません。文中に記載された機密情報の自動匿名化は行いません。
3. 生成前と生成後に編集権限、ノートの削除状態、接続設定を再確認します。生成中に原文が更新された場合は旧版に基づく結果であることを表示します。
4. 結果はブラウザーのメモリにだけ保持し、HTML/Markdownとして実行しません。元ノートを更新しません。コピー・別ノート保存・破棄が選べます。画面を離れると未保存結果は失われます。
5. 別ノート保存は1時間有効な署名を検証し、権限を再確認して、既存のノート作成サービスで保存します。生成ごとの作成キーにより通信再送でも二重作成しません。保存先は元ノートと同じプロジェクトです。新ノートは文字列として保存するため、生成された画像やHTMLが有効になることはありません。

`llm_runs` は利用者・元ノートIDと版・接続・モデル・処理種別・成否・トークン数（提供元が返した場合）・所要時間だけを保持します。プロンプト、本文、生成結果、APIキーは記録しません。ユーザー・プロジェクト・ノートの完全削除時には対応する参照IDをNULLにし、既存の削除操作を妨げません。結果を保存すると通常のノートとして保持され、既存の履歴・ゴミ箱の対象になります。

1利用者につき同時生成1件、過去24時間の合計生成試行回数を制限します。回数上限は実行する接続の設定値を使います。失敗・中断も回数に含め、重複リクエストは再実行しません。タイムアウト、入力文字数、出力トークン上限を設定でき、長い入力を黙って切り捨てません。中断時には接続を閉じますが、接続先の処理や課金の停止までは保証できません。自動再試行はありません。

OpenAIの `store:false` はResponsesの保存を無効にする設定です。提供元の不正利用監視などの保持条件とは別です。送信前に組織のデータ取り扱い方針を確認してください。

## 移行と検証

`0025_knowledge_ai.sql` は接続設定・実行メタデータのテーブルとインデックスだけを追加します。既存ノート、履歴、タスクの変換はありません。アプリ起動時の既存マイグレーション手順を利用します。

`bash tests/run-e2e.sh knowledge-ai` で独立したPostgreSQL・Redis・アプリ・LLMテストダブルを起動してブラウザー検証します。実OpenAIへの通信や料金は発生しません。既存の稼働環境は対象にできず、E2Eガードが新規スタックを検証します。LLM暗号化キーも実行ごとに生成し、終了時にテスト環境を破棄します。MTPLX実機確認は別途、許可したローカル接続で合成ノートを使って実施します。

公式仕様: [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)、[APIのデータ保持](https://developers.openai.com/api/docs/guides/your-data)。

管理者が有効な接続を保存すると、選択したプロジェクトの割り当てをその接続へ切り替えます。他の有効な接続からは該当プロジェクトを外し、同時編集もトランザクションで直列化します。接続を無効にしても別の接続へ自動フォールバックしません。旧設定で複数接続が同じプロジェクトに有効になっている場合は生成を停止し、管理者による再指定を求めます。設定変更前の画面からの生成は再読み込みを案内します。追加マイグレーションは不要です。
