# タイムライン手動行配置 / Asana操作性向上 施策案

2026-11-09 作成。AP_Infra&Sec_P2 の再現検証で判明した
「Atlasの自動レーン配置はAsanaより詰まり、Asanaの行配置を再現できない」
という差分を解消するための設計案。

## 実装状況

Phase 1〜3 を実装済み。

- `task_timeline_rows` テーブル / `PUT /api/tasks/[id]/timeline-row` / 一括解除API
- 固定行 + 自動配置のハイブリッドレイアウト
- 軸ロック式の縦ドラッグ、行ガイド、マイルストーン行固定
- `Alt + ↑/↓`、タッチ長押し
- 固定行同士の重なり警告、空行、プロジェクト/セクション単位の自動整列
- 楽観ロック、監査ログ、セクション移動時の固定解除
- ラベル幅を考慮した自動配置、粗いズームでのラベル内包
- P2プロジェクト（ID 3303）へのAsana行配置インポート

以下は設計判断の記録として残す。

## 操作方法（実装済み）

- バーを上下にドラッグ: 行を固定（40pxスナップ、行ガイド表示）
- バーを左右にドラッグ: 日付変更
- バーの左右端をドラッグ: 反対側の端を固定したまま開始日/期日を変更
  - リサイズ中はバー全体を移動させず、`left` / `width` のみ更新
  - ドラッグ中は幅のCSSトランジションを無効化し、リアルタイムに反映
- `Alt + ↑/↓`: フォーカス中のバーを1行上下
- タッチ: 長押し後に行ドラッグ
- 右クリックメニュー「行の固定を解除」: 自動配置に戻す
- タイムライン「オプション」→「行を自動整列」: プロジェクト全体の固定解除
- 同「選択セクションを自動整列」: セクション単位の固定解除
- 固定行同士が重なる場合は琥珀色の枠で警告

## 現状の課題

- 現在のレーンは「同一セクション内で日付が重ならないタスクを同じ行に自動配置」する方式。
- タスクごとの行を固定する手段がない。
- タイムラインの縦ドラッグは `position`（リスト順）の並べ替えに使われており、
  行の位置そのものは変わらない。
- マイルストーンも日付ベースで自動配置されるため、任意の行に置けない。
- Asana P2 は手動または意味的な行配置をしており、Atlasの自動配置では行数が足りない。
- 四半期ズームでは短いタスクのラベルが隣と干渉する。

## 推奨方針

**「自動配置 + プロジェクト単位の手動行固定」のハイブリッド方式**にする。

- 未指定のタスク/マイルストーンは従来どおり自動レーン配置。
- 上下ドラッグしたタスク/マイルストーンは、その行に固定（`row_index`）。
- 固定行はプロジェクト全体で共有し、再読み込み・ズーム変更でも維持。
- 固定行の周囲に自動タスクを再配置する。
- マイルストーンもタスクと同じ行モデルで自由に上下配置できる。
- リセット（自動配置に戻す / セクションを自動整列）を用意する。

## データモデル

### 新テーブル案

```sql
CREATE TABLE IF NOT EXISTS task_timeline_rows (
  task_id     BIGINT NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  project_id  BIGINT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  row_index   INTEGER NOT NULL CHECK (row_index >= 0),
  updated_by  BIGINT REFERENCES users(id) ON DELETE SET NULL,
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (task_id, project_id)
);
CREATE INDEX IF NOT EXISTS idx_task_timeline_rows_project
  ON task_timeline_rows(project_id, row_index);
```

- `row_index` はセクション内の0始まりの行。
- 行がないタスクは自動配置。
- マルチホーム対応のため `tasks` ではなく `(task_id, project_id)` で保持する。
- セクション移動時は行固定を解除する（または移動先で再検証）。
- プロジェクト複製時は行固定もコピーするか選択できるようにする。

### TaskRow / 取得

- `TaskRow` に `timeline_row: number | null` を追加。
- `getProjectTasks` で `LEFT JOIN task_timeline_rows` して取得。
- タイムラインのレーン計算に `timeline_row` を渡す。

## API

### 行の固定・解除

`PUT /api/tasks/[id]/timeline-row`

```json
{ "project_id": 3303, "row_index": 2 }
```

- `row_index: null` で自動配置に戻す。
- 権限: プロジェクトの `edit` 以上。
- 検証:
  - タスクがプロジェクトに属する（マルチホーム含む）
  - `row_index` は 0〜200 の整数
  - セクションが存在する場合、そのセクション内の行として扱う
- 監査ログ: `task.timeline_row`。
- 競合: `updated_at` による楽観ロック、または last-write-wins + 通知。

### セクション一括リセット

`DELETE /api/projects/[id]/timeline-rows?section_id=...`

- セクション内の固定行をすべて解除。
- ツールバーの「行を自動整列」から呼ぶ。

## レイアウトアルゴリズム

入力:

- セクション内の可視タスク/マイルストーン
- 各タスクの日付区間（マイルストーンは1日）
- `timeline_row`（固定行、null=自動）

処理:

1. 固定行ごとに区間を予約する。
2. 自動配置タスクを開始日・終了日・ID順に処理する。
3. 各タスクについて、以下を満たす最小の行を探す。
   - その行の固定タスクと日付が重ならない
   - その行の既存自動タスクと日付が重ならない
4. 行数 = `max(固定行の最大+1, 自動配置の最大+1)`。
5. 空行は許容する（固定行を下に置いた場合、間の行は空になる）。
6. セクション高さ = 行数 × 40px + 下書き行。

ポイント:

- 固定行は自動配置で動かさない。
- 固定行と重なる自動タスクは、次の空き行へ逃がす。
- 固定行同士が重なる場合は許可するが、重なり警告を表示する。
- マイルストーンも同じアルゴリズム。固定すれば専用行に置ける。

## 操作仕様

### 縦ドラッグ

- バーをポインタダウンし、移動量が閾値（6px）を超えた時点で軸を決定する。
  - `|dx| > |dy|` → 日付変更（既存）
  - `|dy| > |dx|` → 行移動（新規）
- 行移動中は横方向の日付変更をロックする。
- 行は40px単位でスナップ。
- セクション先頭からのY位置で `row_index` を計算。
- ドロップ時に `PUT /api/tasks/[id]/timeline-row`。
- ドロップ中は対象行に水平ガイドとゴーストバーを表示。
- `Esc` でキャンセル。
- 完了時に「行を移動しました」トースト + 元に戻す。

### マイルストーン

- マイルストーンのひし形バーでも同じ縦ドラッグ。
- 横ドラッグは日付変更、縦ドラッグは行固定。
- 固定行はマイルストーン専用行でなくてよい（タスクと同じ行モデル）。
- マイルストーンを空行に置ける。

### リセット

- バー右クリックメニューに「行を自動配置に戻す」。
- ツールバーに「行を自動整列」（セクションまたはプロジェクト全体）。
- 固定行があるタスクには、必要なら小さなピン表示（任意）。

### キーボード / タッチ

- `Alt + ArrowUp/Down` で選択中のタスクを1行上下。
- タッチは長押し（300ms）で行ドラッグを開始。
- バーのツールチップに「上下で行移動 / 左右で日付変更」を明記。

## 衝突ポリシー

推奨: **固定行は自由、自動タスクは逃がす**。

- 固定行に重なる自動タスクは次の空き行へ移動。
- 固定行同士の重なりは許可し、警告アイコンを表示。
- 自動タスク同士は従来どおり重ならない。
- 「重なりを禁止」設定を将来追加できる余地を残す。

## 表示幅を考慮した自動配置（第2段階）

四半期ズームのラベル干渉対策。

- バー幅が狭いタスク/マイルストーンは、外側ラベルを含めた表示幅を推定する。
- ラベル幅は文字数ベースの近似、または canvas `measureText` で算出。
- 表示幅が重なる場合は別行に配置。
- ズーム変更時に再計算する。
- これによりAsanaに近い「ラベルが干渉しない行数」になる。

## P2プロジェクトの完全再現

手動行固定を実装後、検証用プロジェクト `3303` に対して
Asana P2 の行配置を `timeline_row` として設定する。

- Phase2実行計画: WBS=0, 予算承認確認=1
- 要件・RFP: Wave1グループ=0, Wave2グループ=1, 候補ベンダー探索=2
- ソリューション: RFP発行=0, 質疑応答=1, 見積書受領=2, 比較評価=3, NDA/選定完了=4
- 稟議・発注: 2月タスク=0〜4, 役員会=5, 4月タスクはAsana実測に合わせる
- 実装: IDaaS=0

Asana側の未表示タスク（2027年4月以降）は、タイムラインを縦スクロールして
実際の行を確認してから設定する。

## 実装フェーズ

### Phase 1: 基盤（MVP）

- `task_timeline_rows` テーブル
- API（PUT / DELETE）
- TaskRow / 取得 / レイアウトアルゴリズム
- 縦ドラッグ（軸ロック、スナップ、ガイド）
- マイルストーンの行固定
- 自動配置に戻す

### Phase 2: 操作性・安全性

- キーボード操作、タッチ長押し
- 衝突警告、空行表示
- セクション一括自動整列
- 楽観ロック、監査ログ、E2E

### Phase 3: Asana近似

- 表示幅を考慮した自動配置
- P2プロジェクトの行配置インポート
- ズーム変更時の再計算

## テスト観点

- 固定行が再読み込み・ズーム変更後も維持される
- 縦ドラッグで日付が変わらない
- 横ドラッグで行が変わらない
- マイルストーンを任意の行に置ける
- 固定行の周囲に自動タスクが再配置される
- 空行を含むセクションの高さ・左ペインのスペーサーが一致する
- セクション移動時に固定行が解除される
- マルチホームでプロジェクトごとに行が独立する
- 権限（viewerは変更不可）
- 既存の横ドラッグ、右クリックメニュー、依存関係、レーン配置が壊れない

## 主なリスク

- マルチホームの行スコープ
- セクション移動・削除時の整合性
- 固定行と自動配置の再帰的な押し下げ
- モバイルでの縦スクロールとドラッグの競合
- 粗いズームでのラベル干渉
- 複数ユーザー同時編集

## 推奨判断

- まず Phase 1（テーブル + API + 縦ドラッグ + マイルストーン行固定）を実装する。
- 縦ドラッグは「軸ロック方式」を採用し、追加のグリップに頼らない。
- 衝突は「固定行優先・自動タスク退避」とし、固定同士の重なりは警告のみ。
- その上で P2 の行配置を手動設定し、行単位の再現を検証する。
- ラベル干渉対策は Phase 3 で表示幅ベースの自動配置として追加する。
