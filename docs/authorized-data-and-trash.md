# 権限付きデータ取得とノートのゴミ箱

## 読み取り窓口

`lib/services/authorized-data.ts` を、知識と横断検索の読み取り窓口とする。
呼び出し元はサーバーで認証したセッションから `DataActor = { userId }` を渡す。
リクエスト本文・クエリの利用者IDを信用しない。LLM接続は含まない。

- ノートの単件・一覧・履歴・選択ノート、横断検索のタスク・プロジェクト・メッセージ・ノート・添付ファイルが対象。
- 利用者を省略した検索は型と実行時の両方で拒否する。
- SQL実行時の有効な利用者、メンバーシップ・ロール、管理者権限を確認する。権限はキャッシュしない。
- 検索は指定ワークスペースに限定し、既存のマルチホームタスクの可視性を維持する。無権限の検索結果は空。単件・履歴は404。
- 既存HTTP認証・権限ラッパーも維持するので、HTTPでの非メンバーは従来どおり403になる。
- 通常取得は削除ノート・削除プロジェクトを除外する。ゴミ箱は別メソッド・別APIで編集権限を要求する。
- 他の業務画面の全リポジトリを移行するものではない。新しいデータ種別を公開する際は、この窓口に権限付きメソッドを追加する。

## ノートの削除と復元

マイグレーション `0024_knowledge_trash.sql` は削除日時・実行者とインデックスを追加する。
既存の本文、Tiptap JSON、タイトル、版、作成・更新日時、並び順、保存履歴は変更しない。

- `DELETE /api/knowledge/:id?revision=N` はゴミ箱へ移す。現在の版が必須。
- `GET /api/knowledge/trash?project_id=N&offset=N` は100件ずつ取得。編集者・管理者のみ。
- `POST /api/knowledge/:id/restore` に `{ expected_revision: N }` を渡して復元する。
- ゴミ箱では本文と履歴を保持。自動消去・完全削除は実装しない。
- 通常一覧、検索候補、検索結果、リンクによる直接取得、履歴取得、編集、並べ替えから除外する。
- 復元時には同じID・本文・履歴で一覧末尾に戻る。残りのノートの相対順は変えない。
- 削除・復元それぞれで現在の内容を履歴に退避して版を進める。古い編集・削除・復元は409で拒否。
- 操作はプロジェクト→ノートの順でロックし、作成・並べ替え・更新と直列化する。
- ゴミ箱内の作成キーへの再送は409となり、暗黙の復元や重複作成をしない。
- 監査記録は `knowledge.delete` / `knowledge.restore`。本文の更新日時は削除・復元では変更しない。

## 検証

`npm test` に利用者情報の省略・不正値の拒否を追加。
`bash tests/run-e2e.sh knowledge` はラベルと識別子を照合した使い捨て環境で、読み取り窓口のSQL統合テストと、知識編集・並べ替え・ゴミ箱のブラウザーテストを実行する。
`tests/authorized-data-integration.ts` は同じ隔離DBで読み取り窓口のSQLを直接検証する。
実行には `DATABASE_URL=postgres://atlas:atlas@db:5432/atlas_e2e` と一致するDB識別子が必要。
