## 再現方法

Asana のプロジェクトメニュー →「エクスポートまたは同期」→「JSON」で取得した
`/api/1.0/projects/1218489487267518/tasks?opt_expand=(this|subtasks+)` を使用した。

Atlas 側は API で以下を作成した。

- セクション 7 件（空の「セキュリティ標準値設定」を含む）
- トップレベルタスク 26 件

- カスタムフィールド「カテゴリ」（選択肢のみ、値は未設定）

## 差分・注意点

### 1. レーン（Y座標）は手動行固定でAsanaに一致

手動行固定（`task_timeline_rows`）を実装し、P2プロジェクトの26タスクすべてに
Asanaの行番号を設定した。現在は以下の行数で一致している。

| セクション | Asana / Atlas 行数 |
| --- | --- |
| Phase2実行計画 | 2 |
| 推進体制構築 | 1 |
| セキュリティ標準値設定 | 1（空） |
| 要件・RFP／ベンダー選定 | 3 |
| ソリューション＆ベンダー選定 | 5 |
| 稟議・発注 | 8 |
| 実装 | 1 |

- Phase2: WBS=0, 予算承認確認=1
- 要件: Wave1グループ=0, Wave2グループ=1, 候補=2
- ソリューション: RFP発行=0, 質疑=1, 見積書=2, 比較=3, NDA/選定=4
- 稟議: IDaaS=0, SASE=1, ヘルプ=2, ITSM=3, イミュータブル=4, SOC/役員会=5, IR=6, 特権=7
- 実装: IDaaS=0

### 2. 粗いズームのラベル干渉を軽減

- マイルストーンと単日タスクは外側ラベル。
- 複数日タスクは、日/週ズームでは短いバーも外側ラベル。
- 月/四半期/半年/年ズームでは複数日タスクのラベルをバー内に収める。
- 外側ラベルを使う場合のみ、ラベル幅をレーン計算の表示幅に含める。

### 3. サブタスクは未投入

Asana には以下のサブタスクがあるが、タイムラインには表示されないため未作成。

- RFPドラフト版作成 Wave1: 5件
- RFPドラフト版作成 Wave2: 3件

サブタスクの担当者（小山、野田、島崎など）は Atlas のユーザーとは別人のため、
必要ならユーザー作成を含めた別途対応が必要。

### 4. データモデル差

- Asana の「進捗」が空欄のタスクは、Atlas では `progress = 0` になる。
- Asana の「Status」が空欄のタスクは、Atlas 内部では `inbox`（表示は空欄）。
- Asana のプロジェクトメンバー（中嶋、小山、川田）は Atlas には未設定。
  トップレベルタスクの担当者は Asana 側も全件未設定のため、タイムラインには影響しない。

## 結論

- プロジェクト構造・日付・マイルストーン・完了状態・セクション順を再現できた。
- 手動行固定により、Asana P2 の行配置も再現できた。
- ラベル幅を考慮した自動配置と、粗いズームでのラベル内包により、
  ラベル干渉を軽減した。
- サブタスクとプロジェクトメンバーはタイムライン対象外のため未投入。
- データモデル差（進捗の空欄/0、Statusの空欄/inbox）は残る。
